# FlowWatch v0.2.0 实施计划

> 实施状态：十项功能和对应测试均已完成，并已按功能分别提交。`v0.2.0` 已于 2026-08-19 正式发布并完成 GitHub Release 与 Homebrew 安装验证。

## 目标

v0.2.0 要把 FlowWatch 从“能够查询流量数据”推进到“能够发现异常、解释原因、持续提醒并方便维护”。用户应当只通过终端就能完成下面的完整流程：

1. 确认某段时间实际用了多少流量；
2. 找到异常发生的时间；
3. 看到该时间主要是哪些应用以及还有多少流量无法对应到应用；
4. 查看单个应用的长期变化；
5. 在问题复现时临时提高采集精度；
6. 设置流量限额和本机通知；
7. 导出、清理和维护本地数据；
8. 在交互式终端界面中完成常见操作；
9. 安全地检查并安装新版本；
10. 通过 Homebrew 安装和升级。

目标发布版本为 `v0.2.0`。每组功能单独提交，全部通过发布门禁后再创建版本标签。

## 产品原则

- 默认后台资源占用不增加。新分析功能在查询时计算；提醒复用现有每分钟保存时机。
- 实际网卡流量与找到对应应用的流量继续分开显示，不能为了得到 100% 而猜测应用。
- 默认不保存远端域名、IP、端口、数据包内容或原始采样输出。
- 调查模式必须有明确结束时间并自动恢复，不能永久留下高频采样设置。
- 默认输出使用简明中文；技术细节放在详情模式中。
- JSON 和 CSV 保持稳定字段名，便于脚本处理。
- 新增表和设置必须向前兼容现有数据库，升级不得丢失历史数据。
- 共享查询与存储逻辑保持跨平台；LaunchAgent、macOS 通知和 Homebrew 属于平台外壳。

## 功能设计与验收标准

### 1. 查询完整度

`flowwatch apps` 在普通表格下增加所选范围的实际总量、找到对应应用的流量、未找到对应应用的流量和识别率。JSON 输出增加同等摘要，不改变已有应用字段。

验收：

- 摘要使用与应用排行完全相同的有效时间范围；
- 识别结果超过实际总量时保留原值并显示警告；
- 没有网卡数据时不显示误导性的 0% 或 100%；
- 每分钟、五分钟和每日汇总混合范围均有测试。

### 2. 异常时段一键分析

新增：

```sh
flowwatch explain --at "2026-08-18 18:37"
flowwatch explain --period 24h
flowwatch explain --from "2026-08-18 18:30" --to "2026-08-18 18:45"
```

指定时间时自动选择与当时应用明细一致的分析窗口；指定范围时自动找出范围内最高时段。输出实际总量、应用完整度、主要应用、未识别流量、相邻时段对比和可继续执行的命令。`spikes` 的文本结果增加可直接复制的分析提示。

验收：指定分钟、旧五分钟数据、每日汇总、无数据、未识别流量较高和应用流量超量均有明确结果。

### 3. 应用详情与趋势

新增：

```sh
flowwatch app "ChatGPT" --period 7d
flowwatch chart --app "ChatGPT" --period 24h
flowwatch apps --details --period 24h
```

应用选择支持显示名称、完整应用 ID 和无歧义的部分匹配。`app` 显示上传、下载、来源、连接数量、首次和最后出现时间、可执行路径及最高时段。`chart --app` 复用现有图表渲染器，数据来自应用明细而不是网卡总量，并清楚说明其统计边界。

验收：同名多路径、用户别名、模糊选择冲突、混合粒度和旧每日记录均有测试。

### 4. 自动流量报告

新增：

```sh
flowwatch report --period 24h
flowwatch report --date 2026-08-18
flowwatch report --period 30d --compare
flowwatch report --period 24h --json
```

报告包含实际总量、与上一等长时段的变化、应用完整度、主要应用、最高流量时段、未识别流量最高时段和数据健康提示。默认限制篇幅，让用户无需组合多个命令即可得到结论。

验收：比较范围严格等长；自然日遵守本地时区；无上一周期数据时明确说明；JSON 可被稳定解析。

### 5. 临时调查模式

新增：

```sh
flowwatch investigate start --duration 30m
flowwatch investigate status
flowwatch investigate stop
```

调查模式临时使用每秒采样和每分钟应用明细，保存原设置和截止时间，通知 LaunchAgent 重新加载。到期后采集器自动恢复并退出一次，由 LaunchAgent 使用正常设置重新启动。手动停止同样恢复原设置。

验收：

- 时长限制在 5 分钟到 24 小时；
- 重复启动不会覆盖最初的恢复值；
- 程序重启和 Mac 重启后仍能按截止时间恢复；
- 到期、手动停止和数据库异常不会永久留下高频配置；
- 实验记录比较默认模式与调查模式的 CPU、内存、短连接识别效果。

### 6. 流量提醒与限额

新增：

```sh
flowwatch alerts add --daily 10GiB
flowwatch alerts add --monthly 100GiB
flowwatch alerts add --app "ChatGPT" --daily 2GiB
flowwatch alerts list
flowwatch alerts remove <编号>
flowwatch alerts test
```

规则保存在 SQLite。采集器在现有保存周期后检查启用规则，达到阈值时通过 macOS 本机通知提示。通知按规则和统计周期去重；达到 80% 可预警，达到 100% 再提醒一次。应用规则同时显示当前应用识别完整度，避免把不完整数据表达成确定结论。

验收：字节单位解析、日/月边界、80% 与 100% 去重、应用选择、禁用规则和通知失败均有测试。通知失败只写受限日志，不中断采集。

### 7. 应用身份改进

改进 macOS 应用识别：优先显示最外层 `.app` 信息；对脱离应用目录的辅助进程补充父进程和签名信息；保留底层身份供核查。新增用户自定义名称：

```sh
flowwatch config app-names list
flowwatch config app-names set <应用ID> "我的名称"
flowwatch config app-names remove <应用ID>
```

验收：辅助程序、同名不同路径、应用更新导致路径变化、别名设置与删除、原始身份展示均有测试。不能确认父应用时保持原名，不猜测归属。

### 8. 数据导出与管理

新增：

```sh
flowwatch data info
flowwatch data export --period 30d --format csv --output flowwatch.csv
flowwatch data export --period 30d --format json --output flowwatch.json
flowwatch data retention --details 30d --daily 365d
flowwatch data prune --before 2026-01-01 --confirm
flowwatch data compact
```

导出包含网卡总量、应用用量及必要的时间和来源字段，不包含 FlowWatch 本来就不保存的远端信息。删除操作必须给出明确范围并要求 `--confirm`；执行前完成事务和数据库完整性检查。

验收：CSV 转义、JSON 格式、原子写入、拒绝覆盖、保留期限校验、精确清理边界和压缩失败恢复均有测试。

### 9. 自动更新与 Homebrew

新增：

```sh
flowwatch update --check
flowwatch update
```

更新命令读取 GitHub 最新正式版本，按架构下载发布包和 `SHA256SUMS`，校验哈希后调用新二进制完成安装，保留数据库和设置。支持 `--version` 安装指定版本，并拒绝自动降级。

仓库增加 Homebrew Formula 及自动更新脚本。最终目标安装命令为：

```sh
brew install JunieXD/tap/flowwatch
flowwatch install
```

验收：版本比较、架构选择、哈希不匹配、下载中断、已是最新版、指定版本和安装失败均有测试；Formula 在 Apple Silicon 和 Intel 发布包上通过 `brew audit` 与安装测试。

### 10. 交互式终端界面

新增：

```sh
flowwatch dashboard
flowwatch dashboard --period 24h
```

界面使用成熟的终端 UI 库，包含概览、趋势、应用、异常四个视图。方向键移动，`Tab` 切换视图，`Enter` 查看所选应用或异常时段，`r` 刷新，`q` 退出。窗口过小时显示明确提示；非交互终端拒绝启动并给出等价 CLI 命令。

验收：状态转换、选择边界、窗口缩放、无数据、无颜色和退出恢复终端均有测试。界面只在用户主动运行时占用资源，不增加后台依赖。

## 存储与模块边界

计划新增以下 SQLite 内容：

- `alert_rules`：规则类型、应用 ID、阈值、启用状态和创建时间；
- `alert_events`：规则、统计周期、阶段和通知时间，用于去重；
- `app_names`：稳定应用 ID 到用户显示名称的映射；
- `settings` 中的调查模式截止时间和原始设置。

查询摘要、应用时间序列、范围比较和导出接口放在 `flowwatch-store`，保持平台无关。macOS 通知、LaunchAgent 重启、自更新替换和进程身份补充放在应用或 `flowwatch-macos`。终端图表与 TUI 只消费查询模型，不直接拼接 SQL。

## 发布门禁

正式发布前必须全部通过：

```sh
cargo fmt --all -- --check
cargo clippy --locked --workspace --all-targets -- -D warnings
cargo test --locked --workspace
cargo +1.88.0 test --locked --workspace
cargo +1.88.0 build --locked --release --workspace
scripts/check-release.sh v0.2.0 target/release/flowwatch
scripts/test-installer.sh
```

推送 `main` 后等待持续检查完成，再创建 `v0.2.0` 带说明标签。发布完成后重新下载两种架构包和 `SHA256SUMS`，校验哈希，并至少实际运行版本、帮助、报告、应用趋势、更新检查和 Dashboard 启动退出测试。

## 本版本暂不包含

- 需要 Apple Developer 账号、签名和 entitlement 的 Network Extension 增强模式；
- 默认保存远端域名、IP、端口或数据包内容；
- Windows 采集后端；
- 睡眠唤醒、网络切换和 Clash 重启的专项恢复机制。

这些内容继续保留架构扩展点，但不阻塞 v0.2.0。
