# 调查模式实验记录

> 实验日期：2026-08-18 至 2026-08-19

本实验用于确认调查模式是否在可接受的资源代价下提高短连接的应用识别机会。结果只说明本机本次负载，不应理解为所有 Mac 上的固定性能数字。

## 环境

- 设备：`Mac16,10`，Apple Silicon（`arm64`）
- 系统：macOS 26.5.2（25F84）
- 程序：优化后的 release 构建
- 默认模式：每 3 秒采样、每五分钟保存应用明细
- 调查模式：每 1 秒采样、每分钟保存应用明细
- 两组使用独立 SQLite 数据库，不修改正式采集服务或用户历史数据

## 资源占用

两种模式分别空载运行约 20 秒，并使用 `/usr/bin/time -l` 记录 FlowWatch 及其子进程资源：

| 模式 | 实际运行时间 | 用户 CPU | 系统 CPU | 折算单核占用 | 最大常驻内存 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 默认模式 | 22.34 秒 | 0.10 秒 | 0.04 秒 | 约 0.6% | 约 10.2 MiB |
| 调查模式 | 20.02 秒 | 0.29 秒 | 0.09 秒 | 约 1.9% | 约 10.6 MiB |

调查模式的 CPU 时间约为默认模式的三倍，与采样频率从每 3 秒提高到每 1 秒一致；绝对占用仍低于单核 2%。峰值内存增加约 0.4 MiB，没有出现随采样次数持续增长的迹象。

## 短连接识别

为避免系统代理和其他进程污染结果，实验使用单独命名的系统 `curl` 探针，并通过 `--noproxy '*'` 建立直连。每组在采集器运行期间连续发起五个请求；每个请求限制为约 100 KiB/s，并在 2 秒后结束。

结果：

- 默认模式没有记录到 `curl`；五个连接都只进入网卡实际总量。
- 调查模式记录到 `curl` 的 4 个连接，应用记录约 1.0 MiB。
- 调查模式仍遗漏了 1 个连接，符合“第一次观察只建立基线”和采样时点不保证覆盖所有短连接的设计边界。

结论是调查模式能显著增加持续时间介于 1 到 3 秒之间连接的识别机会，但不能提供逐连接或逐数据包的完整统计。CLI 和 README 必须继续使用“提高识别机会”而不是“保证完整识别”的表述。

## 隔离与恢复验证

端到端测试还验证了：

- 指定测试数据库启动调查模式不会重启默认 LaunchAgent；
- 采集器确实按每 1 秒运行并写入每分钟应用记录；
- `status` 和 `investigate status` 能显示截止时间与剩余时间；
- 手动停止后，基础的 3 秒采样与五分钟明细设置保持不变；
- 到期状态会被清除，下一次采集按基础设置启动。
